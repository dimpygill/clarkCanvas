What this project does
The full picture in plain language

You type how you're feeling into the terminal. Python sends that to Claude, the AI figures out which mood keyword matches what you said, and then Python looks that keyword up in a dictionary to find a movie recommendation.

terminal
You type a feeling
→
matcher.py
Claude API call
→
matcher.py
Dictionary lookup
→
terminal
Movie printed

The entire project is one Python file and one .env file. No website, no database, no complicated setup.

💡
The key insight The dictionary does the actual lookup — it knows nothing about natural language. The AI's only job is to convert whatever the user typed into one clean keyword that matches a dictionary key. This is exactly how dictionaries are used in real applications.

The .gitignore in this project contains three entries. Each is excluded for a different reason:

EntryWhy it's ignored
.env Contains your secret API key. If this file were uploaded to GitHub it would be publicly visible — anyone could use your key and run up your bill. This is the most important entry in the file.
venv/ Your virtual environment folder can be 50–200MB and contain thousands of files — the actual installed copies of every package. There is no point uploading all of that. Anyone who clones your project can recreate it in seconds by running pip install -r requirements.txt. That is exactly why requirements.txt exists — it is the lightweight shopping list, venv/ is the shopping itself. Share the list, not the bags.
__pycache__/ and *.pyc Every time Python runs a .py file it compiles it into a faster binary format and saves it in a __pycache__ folder as a .pyc file. These are machine-generated — you never write them, Python creates them automatically. They get recreated the next time the code runs, so there is nothing to save. They also contain absolute file paths from your computer, which makes them useless on anyone else's machine anyway. The *.pyc pattern catches any compiled files that end up outside the cache folder.
✅
The general rule for .gitignore If a file is auto-generated, can be recreated easily, is specific to your machine, or contains secrets — leave it out of Git. Only commit files that a human wrote and that are needed to understand or run the project.

LineWhat it does
import osLoads Python's built-in os module. We use it on one line: os.environ.get("ANTHROPIC_API_KEY") — which reads the API key from the environment.
import jsonLoads Python's built-in json module. Claude returns its answer as a JSON string. json.loads() converts that string into a Python dictionary we can work with.
import anthropicLoads the Anthropic SDK — the library that handles sending requests to Claude and receiving responses. Without this you'd have to write raw HTTP requests yourself.
from dotenv import load_dotenvImports just the load_dotenv function from the python-dotenv package. from X import Y is how you pull one specific thing out of a library.
load_dotenv()Reads your .env file and loads everything in it into os.environ. After this line runs, os.environ.get("ANTHROPIC_API_KEY") works. This must be called before any code that needs the key.
ℹ️
import vs from X import Y import os loads the whole module — you then access things inside it as os.environ. from dotenv import load_dotenv pulls out just one function — so you can call it as load_dotenv() instead of dotenv.load_dotenv(). Both styles are valid.
Why must load_dotenv() be called before the API client is created?
Correct. load_dotenv() must run first so the key is available in os.environ by the time the next line tries to read it.
Think about what load_dotenv() does — it puts the key into os.environ. If the client is created before that happens, the key is still missing and the client is created with None.

The Python dictionary
matcher.py — MOVIES

This is the core of the project. A dictionary maps mood keywords to movie data. The AI never picks the movie — it just figures out the right keyword, and then Python does a simple lookup.

matcher.py
MOVIES = {
    "happy":    {"title": "The Grand Budapest Hotel", "genre": "Comedy · Adventure", "year": "2014"},
    "sad":      {"title": "Inside Out",               "genre": "Animation · Drama",  "year": "2015"},
    "scared":   {"title": "Get Out",                  "genre": "Horror · Thriller",  "year": "2017"},
    "romantic": {"title": "Crazy Rich Asians",        "genre": "Romance · Comedy",   "year": "2018"},
    "bored":    {"title": "Inception",                "genre": "Sci-Fi · Thriller",  "year": "2010"},
    "excited":  {"title": "Everything Everywhere All at Once", "genre": "Action · Sci-Fi", "year": "2022"},
}
ConceptExplanation
MOVIES = { }Creates a dictionary called MOVIES. The uppercase name is a Python convention meaning this value never changes — it's a constant.
"happy": { ... }One key-value pair. The key is "happy" (a string). The value is another dictionary containing the movie details. This is called a nested dictionary.
{"title": ..., "genre": ..., "year": ...}The inner dictionary. It has three keys of its own: title, genre, and year. Each maps to a string value.
Six entries totalSix moods the AI can detect: happy, sad, scared, romantic, bored, excited. If the AI detects anything else, the lookup returns None and the program shows a helpful message.
💡
Why all-caps for MOVIES? In Python, variables written in ALL_CAPS are treated as constants — values that are defined once and never changed. It's a convention, not enforced by the language, but it tells anyone reading the code "don't modify this."
What does MOVIES["sad"]["title"] return?
Correct. MOVIES["sad"] returns the inner dictionary {"title": "Inside Out", ...}, and then ["title"] pulls out just the title string.
Work through it step by step. MOVIES["sad"] gives you the inner dictionary. Then ["title"] looks up the title key inside that inner dictionary.

The extract_mood() function
matcher.py — calling Claude and parsing the response

This function takes whatever the user typed, sends it to Claude, and gets back a mood keyword and a movie blurb. It's the bridge between natural language and the dictionary.

matcher.py — extract_mood()
def extract_mood(user_input):
    keys = ", ".join(MOVIES.keys())

    prompt = f"""The user says: "{user_input}"

Map their mood to exactly one of these dictionary keys: {keys}

Respond with JSON only, no explanation:
{{"mood": "<one of the keys above, or null if none fit>",
  "blurb": "<one sentence recommending the matched movie>"}}"""

    message = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=200,
        messages=[{"role": "user", "content": prompt}]
    )

    data = json.loads(message.content[0].text.strip())
    return data.get("mood"), data.get("blurb", "")
LineWhat it does
def extract_mood(user_input):Defines a function called extract_mood. It accepts one argument — the text the user typed — and gives it the name user_input inside the function.
keys = ", ".join(MOVIES.keys())MOVIES.keys() returns all the mood words: ["happy", "sad", "scared", ...]. ", ".join(...) joins them into one string: "happy, sad, scared, romantic, bored, excited". This gets injected into the prompt so Claude knows what the valid options are.
prompt = f"""..."""An f-string — a string that can contain {variable} placeholders. Python replaces {user_input} and {keys} with their actual values before sending. The triple quotes """ let the string span multiple lines.
client.messages.create(...)Sends the prompt to Claude and waits for a response. This is where the internet call actually happens.
model="claude-opus-4-5"Specifies which Claude model to use. Different models have different speeds and costs — Opus is the most capable.
max_tokens=200Limits how long Claude's response can be. 200 tokens is plenty for a short JSON object. This keeps the cost low and prevents runaway responses.
messages=[{"role": "user", "content": prompt}]The conversation history sent to Claude. role is always "user" here since we're sending a question. content is the prompt text.
message.content[0].textClaude's response. content is a list of response blocks — we take the first one ([0]) and read its text property. This gives us the raw JSON string Claude returned.
.strip()Removes any leading or trailing whitespace from the string. Claude sometimes adds a newline at the end — this cleans it up before parsing.
json.loads(...)Converts the JSON string {"mood": "sad", "blurb": "..."} into a Python dictionary. After this line, data is a regular Python dict we can read with data["mood"].
return data.get("mood"), data.get("blurb", "")Returns two values at once — the mood keyword and the blurb. .get("blurb", "") means "return the blurb, or an empty string if it's missing." Python lets functions return multiple values separated by a comma.
ℹ️
Why ask Claude for JSON? JSON is a structured format Python can parse reliably with json.loads(). If we just asked Claude to "say the mood word", it might reply with "The mood is sad." or "sad!" — inconsistent text that's hard to extract cleanly. Asking for JSON gives us a predictable structure every time.
Why do we pass keys into the prompt instead of writing the mood words directly in the prompt text?
Exactly. If you add "nostalgic" to MOVIES, the prompt updates automatically because it reads MOVIES.keys() every time. No need to edit the prompt separately.
Think about what happens when you add a new mood. If the keys were hardcoded in the prompt string, you'd have to remember to update the prompt too — two places to change instead of one.

The main() function
matcher.py — user input, dictionary lookup, terminal output

This is the part the user actually sees. It collects input, calls extract_mood(), does the dictionary lookup, and prints the result.

matcher.py — main()
def main():
    print("\n🎬  Movie Mood Matcher")
    print("─" * 30)

    user_input = input("\nHow are you feeling? ")

    if not user_input.strip():
        print("Please describe how you're feeling.")
        return

    print("\nThinking...\n")

    mood, blurb = extract_mood(user_input)
    movie = MOVIES.get(mood)

    if movie is None:
        print(f"Mood detected : {mood}")
        print("Sorry, that mood isn't in the dictionary yet.")
        print(f'Try adding: "{mood}": {{"title": "...", "genre": "...", "year": "..."}}')
    else:
        print(f"🎯 Mood detected : {mood}")
        print(f"🎥 Movie         : {movie['title']}")
        print(f"🎭 Genre         : {movie['genre']}")
        print(f"📅 Year          : {movie['year']}")
        print(f"💬 Why           : {blurb}")

    print()


if __name__ == "__main__":
    main()
LineWhat it does
def main():Defines the main function — the entry point of the program. Everything the user interacts with happens here.
print("\n🎬 Movie Mood Matcher")Prints the title to the terminal. \n is a newline character — it adds a blank line before the text for breathing room.
print("─" * 30)Prints a horizontal line made of 30 dash characters. "─" * 30 repeats the string 30 times — a quick way to draw a divider.
user_input = input("How are you feeling? ")Pauses the program and waits for the user to type something and press Enter. Whatever they type is stored in user_input.
if not user_input.strip():Checks if the user pressed Enter without typing anything. .strip() removes spaces — so even pressing the space bar counts as empty. if not means "if this is empty".
returnExits the function immediately. Nothing below this line runs. Used here to stop the program cleanly when there's no input.
mood, blurb = extract_mood(user_input)Calls the function we wrote earlier and receives two return values at once. Python unpacks them into two separate variables: mood gets the keyword, blurb gets the recommendation sentence.
movie = MOVIES.get(mood)The dictionary lookup. .get() returns the inner dictionary if the key exists, or None if it doesn't. This is the core operation the whole project is built around.
if movie is None:Handles the case where the AI returned a mood that isn't a key in the dictionary. Shows a helpful message and suggests the exact code to add the new mood.
f"🎯 Mood detected : {mood}"An f-string. Python replaces {mood} with the actual value of the variable — for example "sad". The emoji is just a character in the string.
movie['title']Reads the title key from the inner dictionary. Since movie is a dictionary like {"title": "Inside Out", ...}, this returns "Inside Out".
if __name__ == "__main__":Python sets __name__ to "__main__" when you run a file directly. This line means "only call main() if this file was run directly, not if it was imported by another file." It's the standard way to make a Python file runnable.
main()Calls the main() function to actually start the program.
What happens if MOVIES.get(mood) returns None?
Correct. .get() never crashes — it returns None for missing keys, and the if movie is None block handles it gracefully by telling the user how to add the new mood.
A crash would happen with MOVIES[mood] if the key is missing. But .get() returns None instead, and the if movie is None check handles that case safely.
