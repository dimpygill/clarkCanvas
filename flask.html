Python is a general-purpose language. Flask is a Python package that adds exactly one thing: the ability to receive browser requests and send responses back. This tutorial shows the difference with side-by-side examples you can interact with.

Flask Flask-specific — needs Flask installed
01 The core difference

What each one actually is

Before writing a single line, it's worth being clear: you don't choose between Python and Flask — you use both together. Flask is written in Python. Every Flask app is a Python program. The question is what Flask adds on top.

Python

A general-purpose programming language. Can do data science, automation, AI, games, file processing — anything. Has no concept of web servers, URLs, or browsers built in.

+

Flask

A Python package (someone else's code you install) that adds exactly one thing: the ability to listen for HTTP requests from a browser and send responses back. Built entirely in Python.

Python only

Variables & functions

All the basics — loops, conditions, classes, strings. Flask uses these but doesn't invent them.

Python only

Libraries & imports

import math, import pandas — Python's built-in and third-party packages.

Flask adds

URL routing

Connecting a URL like /about to a Python function that runs when someone visits it.

Flask adds

Request / response

Reading what the browser sent (form data, JSON, headers) and sending back HTML, JSON, or anything else.

Flask adds

A web server

app.run() starts a server that listens on a port so a browser can reach it.

Python only

Everything else

Database calls, business logic, calculations, file I/O — all plain Python that Flask simply calls when a request arrives.

The most common misconception: thinking Flask and Python are alternatives. They're not. You write Flask apps in Python. Flask is just a set of tools you import — like importing pandas or math, except this one lets your code respond to web requests.
02 Pure Python

Python without Flask — just functions

Here's what pure Python can do — define functions, do math, work with strings. This code runs perfectly without Flask. You call these functions by name in your code, not by visiting a URL.

pure_python.py — no Flask anywherePython
# Pure Python — no Flask, no web server, just functions

def greet(name):
    return f"Hello, {name}!"

def square(n):
    return n * n

def is_even(n):
    return n % 2 == 0

# You call these directly in your code:
print(greet("Ada"))       # Hello, Ada!
print(square(7))         # 49
print(is_even(4))        # True
Key point: these functions exist and work. But only your Python code can call them — by name, in the same file or after importing. A web browser has no way to call greet("Ada"). There is no URL, no server, no way in from the outside. That's the gap Flask fills.

Now let's see what happens when Flask enters the picture. The functions don't change at all — Flask just gives each one a URL so a browser can reach it.

🐍 Pure Python — same functions
def greet(name):
    return f"Hello, {name}!"

def square(n):
    return n * n

# Called by name in code:
greet("Ada")
square(7)
🌶 With Flask — same functions, now on URLs
@app.route("/greet/<name>")
def greet(name):
    return f"Hello, {name}!"

@app.route("/square/<int:n>")
def square(n):
    return f"{n} squared = {n*n}"

# Called by visiting a URL:
# /greet/Ada → "Hello, Ada!"
# /square/7  → "7 squared = 49"
Notice what didn't change: the function bodies are identical. Flask only added the @app.route() decorator above each one. That decorator is the whole of what Flask does to a function — attach a URL to it.
03 Enter Flask

The anatomy of a Flask app

A Flask app is a Python file that imports Flask, creates one app object, and defines routes. Let's read every line and understand which parts are Python and which parts are Flask.

app.py — annotated line by line
from flask import Flask    # ← FLASK: import the Flask tool (like import math)

app = Flask(__name__)       # ← FLASK: create one app object. __name__ is Python.

@app.route("/")           # ← FLASK: attach URL "/" to the function below
def home():                # ← PYTHON: a regular function definition
    return "Hello!"        # ← PYTHON: a regular return statement

if __name__ == "__main__": # ← PYTHON: standard "run this file directly" check
    app.run(debug=True)    # ← FLASK: start the web server

Flask(__name__)

Creates the application

One object that holds all your routes. __name__ tells Flask where to look for template files — that part is Python, the rest is Flask.

@app.route("/")

The decorator

A Python decorator is a function that wraps another function. Flask uses it to register the URL in a lookup table. When / is visited, Flask finds home() in that table and calls it.

app.run()

Starts the server

Tells Python to listen on port 5000 (by default). Without this, the file runs and immediately exits — nothing to receive browser requests.

return "Hello!"

Return value becomes the response

Flask takes whatever your function returns and sends it to the browser as the HTTP response body. A string becomes a plain text page.

04 Routes

Try it: type a URL, see which function runs

Here's an app with four routes. The fake browser below works exactly like Flask's router. Type any URL and see what you get — and whether it was Python or Flask that produced it.

🐍 Python — the function bodies
def home():
    return "Welcome!"

def about():
    return "Built with Flask."

def contact():
    return "hello@example.com"

def pricing():
    price = 9.99 * 12    # Python math
    return f"${price}/year"

@app.route("/")
def home(): ...

Try these:

/ /about /contact /pricing /blog /ABOUT
Try /blog and /ABOUT. Flask does exact string matching — /ABOUT is different from /about, and /blog has no route, so both return 404. Routing is not fuzzy; it's case-sensitive and exact.
05 Dynamic URLs

One route, any number of pages

You don't write a separate route for every user or every product. Put a variable in angle brackets — Flask extracts it from the URL and passes it straight into your function as an argument.

🐍 Python — function takes an argument
def profile(name):
    return f"Profile: {name}"

def power(base, exp):
    result = base ** exp  # Python math
    return f"{base}^{exp} = {result}"

def item(category, item_id):
    return f"Item {item_id} in {category}"
🌶 Flask — URL pieces become arguments
@app.route("/user/<name>")
def profile(name): ...

@app.route("/power/<int:base>/<int:exp>")
def power(base, exp): ...
# int: converts to integer automatically

@app.route("/shop/<category>/<int:item_id>")
def item(category, item_id): ...
200 OK
Profile: ada
Flask matched /user/<name> → called profile(name="ada").

Try these:

/user/ada /user/grace /power/2/10 /power/3/3 /shop/books/42 /shop/shoes/7 /power/two/3
Python's ** operator does the math. Flask just extracted base and exp from the URL and handed them to your function. The actual calculation — base ** exp — is pure Python, nothing to do with Flask.
Try /power/two/3. The int: converter in <int:base> only matches digits, so "two" fails before your function ever runs. Flask rejected it at the routing layer. You didn't write that validation — Flask gave it to you.
06 GET vs POST

Same URL, two different actions

Every HTTP request has a method — GET means "give me something to read," POST means "here's data I'm sending." Flask lets you route the same URL to different functions depending on which method arrived.

app.py
from flask import Flask, request, jsonify  # ← FLASK imports

notes = []                                   # ← PYTHON: plain list

@app.route("/notes", methods=["GET"])     # ← FLASK: only handles GET
def list_notes():
    return f"You have {len(notes)} notes"  # ← PYTHON: f-string, len()

@app.route("/notes", methods=["POST"])    # ← FLASK: only handles POST
def add_note():
    data = request.get_json()             # ← FLASK: read what browser sent
    notes.append(data["text"])            # ← PYTHON: list.append()
    return f"Saved: {data['text']}"        # ← PYTHON: f-string
200 OK
You have 0 notes
A GET to /notes → ran list_notes().
Click POST, then GET again. The count goes up because POST called add_note() which ran notes.append() — that's Python's list doing the work. Flask only decided which function to call. Everything inside the function is Python.
07 What you return

Return values become HTTP responses

A Python function can return anything — a string, a number, a list. Flask intercepts that return value and turns it into an HTTP response. What you return determines what the browser sees.

Return value Python side What Flask sends to browser
String return "Hello!" Plain text page with body "Hello!"
HTML string return "<h1>Hello</h1>" A rendered HTML page
jsonify() return jsonify({"name": "Ada"}) JSON response with correct Content-Type header
Tuple with status return "Not found", 404 Response with a custom HTTP status code
render_template() return render_template("page.html") Renders a Jinja2 template file and sends the result
🐍 Python — building the data
def get_user(user_id):
    # All Python: dict, math, string
    user = {
        "id": user_id,
        "name": "Ada",
        "score": user_id * 10
    }
    return user  # Python dict
🌶 Flask — converting to HTTP response
from flask import jsonify

@app.route("/user/<int:user_id>")
def get_user(user_id):
    user = {
        "id": user_id,
        "name": "Ada",
        "score": user_id * 10
    }
    return jsonify(user)  # Flask wraps it
jsonify() is Flask, dicts are Python. You build the data structure using plain Python — dicts, lists, strings. jsonify() is the Flask function that serializes it to JSON and sets the right HTTP headers so the browser understands what it's receiving.

08 Inside the Flask package

What Flask is actually made of

When you run pip install flask, you get a package with six layers. You'll only use a handful of them day to day — but knowing the map stops you from being confused when you see things like from flask import session or g.

Flask package — the full mapFlask
Flask Package
│
├── Classes
│   ├── Flask           # the application object — app = Flask(__name__)
│   └── Blueprint       # organise routes into reusable groups
│
├── Functions
│   ├── render_template()  # find an HTML file and fill in variables
│   ├── jsonify()          # turn a Python dict into a JSON response
│   ├── redirect()         # send the browser to a different URL
│   ├── url_for()          # build a URL from a function name
│   ├── abort()            # immediately return an error code (e.g. 404)
│   └── make_response()    # build a custom HTTP response object
│
├── Objects
│   ├── request        # the current incoming HTTP request
│   ├── session        # stores data across multiple requests (cookie-backed)
│   ├── current_app    # the running Flask application
│   └── g              # scratch space for one request's lifetime
│
├── Routing System
│   └── @app.route()   # decorator that maps URLs to functions
│
├── Template Engine
│   └── Jinja2          # HTML templates with {{ variables }} and {% logic %}
│
└── Development Server
    └── app.run()      # starts the server on localhost:5000
You won't use all of these at once. Most apps day-to-day only need: Flask, request, render_template, jsonify, redirect, url_for, and session. The rest exist for specific situations.

Jinja2 — Flask's template engine

  
Templates let you write HTML with placeholders that Flask fills in at request time. The {{ }} syntax is Jinja2, not Python — but it feels very similar.


  

    

      
🐍 Python — pass data to template


@app.route("/user/<name>")
def profile(name):
    score = len(name) * 10  # Python
    items = ["flask", "python"]
    return render_template(
        "profile.html",
        name=name,
        score=score,
        items=items
    )

    

    

      
🌶 Jinja2 — templates/profile.html


<!-- {{ }} prints a value -->
<h1>Hello, {{ name }}!</h1>
<p>Score: {{ score }}</p>

<!-- {% %} is logic -->
{% for item in items %}
  <li>{{ item }}</li>
{% endfor %}

<!-- conditional -->
{% if score > 50 %}
  <p>High scorer!</p>
{% endif %}

    

  


  

    Jinja2 is Flask's template engine. It's a separate package Flask pulls in automatically. The {{ }} and {% %} syntax is Jinja2, not Python — but the logic (if, for, variables) looks almost identical to Python on purpose.
