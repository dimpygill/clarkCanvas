What this project does
The full picture before we look at any code

This project is a web app where you type how you're feeling and it recommends a movie. The interesting part is how it works — a Python dictionary does the actual lookup, and the Claude AI figures out which dictionary key matches what you typed.

Here's the full flow from user input to movie recommendation:

browser
User types mood
→
app.py
Flask receives form
→
matcher.py
Claude API call
→
matcher.py
Dict lookup
→
index.html
Result shown
💡
Why use a dictionary here? The dictionary is the logic layer of this app. The AI's only job is to extract a single keyword from what the user typed. Once it has that keyword, Python does a simple dictionary lookup — MOVIES.get(mood) — to find the result. This is exactly how dictionaries are used in real applications: fast key-to-value lookups.

The Python dictionary
matcher.py — the core data structure

The dictionary is the heart of this project. Open matcher.py and the first thing you'll see is MOVIES.

matcher.py 
import os
import json
import anthropic

# Each key is a mood string.
# Each value is a nested dictionary with movie details.
MOVIES = {
    "happy":    {"title": "The Grand Budapest Hotel", "genre": "Comedy · Adventure", "year": "2014"},
    "sad":      {"title": "Inside Out",               "genre": "Animation · Drama",  "year": "2015"},
    "scared":   {"title": "Get Out",                  "genre": "Horror · Thriller",  "year": "2017"},
    "romantic": {"title": "Crazy Rich Asians",        "genre": "Romance · Comedy",   "year": "2018"},
    "bored":    {"title": "Inception",                "genre": "Sci-Fi · Thriller",  "year": "2010"},
    "excited":  {"title": "Everything Everywhere All at Once", "genre": "Action · Sci-Fi", "year": "2022"},
}

Notice that the values are themselves dictionaries — this is called a nested dictionary. Each mood key maps to an inner dictionary with three fields: title, genre, and year.

Dictionary conceptWhere it appears in this project
Key-value pair"happy": {...} — mood is the key, movie data is the value
Nested dictionaryEach value is itself a dictionary: {"title": "...", "genre": "...", "year": "..."}
.get() with defaultMOVIES.get(mood) returns None if the key doesn't exist — no crash
Iterating with .items()Used in the HTML template to render every row in the dictionary viewer
Checking membershipThe not-found state triggers when MOVIES.get(mood) returns None
✅
Why .get() instead of MOVIES[mood]? Using square brackets — MOVIES["melancholy"] — raises a KeyError and crashes if the key doesn't exist. The .get() method returns None instead, which we can handle gracefully and show a helpful message to the user.
What does MOVIES.get("angry") return if "angry" is not a key in the dictionary?
Correct. .get() returns None by default when a key is missing. You can also supply a fallback: MOVIES.get("angry", "Mood not found").
Not quite. MOVIES["angry"] would raise a KeyError, but MOVIES.get("angry") safely returns None.

Calling the Claude API
matcher.py — extract_mood() and get_movie()

The dictionary only understands exact keys like "happy" or "sad". But users type things like "I feel kind of gloomy today". That's where the AI comes in — it reads the free-text input and maps it to one of our dictionary keys.

matcher.py — setting up the client 
# os.environ.get() reads the key from your .env file.
# python-dotenv loads .env automatically when app.py starts.
client = anthropic.Anthropic(api_key=os.environ.get("ANTHROPIC_API_KEY"))
matcher.py — extract_mood() 
def extract_mood(user_input: str) -> tuple[str | None, str]:
    # Build a string of all valid keys to include in the prompt.
    keys = ", ".join(MOVIES.keys())
    # keys = "happy, sad, scared, romantic, bored, excited"

    prompt = f"""The user says: "{user_input}"

Your job is to map their mood to exactly one of these dictionary keys: {keys}

Respond with a JSON object only — no explanation, no markdown fences:
{{"mood": "<one of the keys above, or null if none fit>",
  "blurb": "<one sentence recommending the matched movie>"}}}"""

    # Send the prompt to Claude and get a response.
    message = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=200,
        messages=[{"role": "user", "content": prompt}]
    )

    # The response is a JSON string. Parse it.
    raw  = message.content[0].text.strip()
    data = json.loads(raw)
    return data.get("mood"), data.get("blurb", "")
matcher.py — get_movie() 
def get_movie(mood: str | None, blurb: str) -> dict | None:
    movie = MOVIES.get(mood)   # ← the dictionary lookup
    if movie is None:
        return None
    return {"mood": mood, "blurb": blurb, **movie}
ℹ️
What is **movie? The ** operator unpacks a dictionary into keyword arguments. So {"mood": mood, "blurb": blurb, **movie} merges the mood and blurb with the movie's title, genre, and year — into one flat dictionary that's easier for the template to use.
LineWhat it does
keys = ", ".join(...)Builds "happy, sad, scared, ..." from the dictionary keys — injected into the prompt so Claude knows what's valid
client.messages.create()Sends the prompt to Claude and waits for a response
max_tokens=200Limits the response length — we only need a short JSON object, not an essay
message.content[0].textThe raw text Claude returned — a JSON string like {"mood": "sad", "blurb": "..."}
json.loads(raw)Converts that JSON string into a Python dictionary so we can read the values
Why do we pass keys into the prompt instead of hardcoding mood names there?
Exactly. If you add "nostalgic" to MOVIES, the prompt updates automatically — no need to change the prompt text by hand.
Think about what happens when you add a new mood to the dictionary. If the keys were hardcoded in the prompt, you'd have to update two places instead of one.

The Flask app
app.py — routing and request handling

Flask is a lightweight Python web framework. app.py has one job: receive HTTP requests from the browser, call the right functions, and send back a rendered HTML page.

app.py 
from flask import Flask, render_template, request
from dotenv import load_dotenv
from matcher import extract_mood, get_movie, MOVIES

load_dotenv()   # reads ANTHROPIC_API_KEY from .env into os.environ

app = Flask(__name__)
app.secret_key = "dev-secret"

@app.route("/", methods=["GET", "POST"])
def index():
    result         = None
    not_found_mood = None
    mood_input     = None
    error          = None

    if request.method == "POST":
        # Read what the user typed into the form field named "mood_input".
        mood_input = request.form.get("mood_input", "").strip()

        if not mood_input:
            error = "Describe how you're feeling first."
        else:
            try:
                mood, blurb = extract_mood(mood_input)   # AI call
                result = get_movie(mood, blurb)            # dict lookup
                if result is None:
                    not_found_mood = mood or "unknown"
            except Exception as e:
                error = f"Something went wrong: {e}"

    return render_template(
        "index.html",
        result=result,
        not_found_mood=not_found_mood,
        mood_input=mood_input,
        error=error,
        movies=MOVIES,   # passed to the template to render the dict viewer
    )

if __name__ == "__main__":
    app.run(debug=True)
ConceptExplanation
@app.route("/")Registers the URL / — so visiting http://127.0.0.1:5000 calls this function
methods=["GET", "POST"]GET = page load. POST = form submission. Same URL handles both.
request.method == "POST"Only run the AI logic when the user actually submitted the form
request.form.get()Reads the value from the HTML form field whose name attribute is "mood_input"
render_template()Finds templates/index.html, fills in the Jinja2 variables, returns finished HTML
try / exceptIf the API call fails (bad key, no internet), shows a friendly error instead of crashing
💡
GET vs POST — why does it matter? When you first visit the page the browser sends a GET request — no form data, so we just show the empty UI. When you click "Match mood" the browser sends a POST request with the form data attached. The if request.method == "POST" check separates these two cases cleanly.

The HTML template
templates/index.html — Jinja2 and the UI

The HTML file lives inside the templates/ folder. Flask requires that exact folder name. The file uses Jinja2 — a templating language that lets you embed Python-like expressions directly inside HTML.

⚠️
This is why opening index.html directly shows raw code. A browser reads HTML, not Jinja2. The {{ }} and {% %} tags are instructions for Flask, not the browser. Always open the app through http://127.0.0.1:5000.

Here are the key Jinja2 patterns used in this project:

templates/index.html — displaying the result 
<!-- {% if %} checks whether Flask passed a result -->
{% if result %}
  <div class="result-card">
    <div class="movie-title">{{ result.title }}</div>
    <div class="movie-meta">{{ result.genre }} · {{ result.year }}</div>
    <div class="movie-blurb">{{ result.blurb }}</div>
  </div>
{% endif %}
templates/index.html — looping over the dictionary 
<!-- Flask passed movies=MOVIES so we can loop over it here -->
{% for key, data in movies.items() %}
  <div class="dict-row {% if result and result.mood == key %}hit{% endif %}">
    <span class="dict-key">"{{ key }}"</span>
    <span class="dict-val">{{ data.title }}</span>
  </div>
{% endfor %}
templates/index.html — the form 
<form method="POST" action="/">
  <input
    type="text"
    name="mood_input"         <!-- must match request.form.get("mood_input") in app.py -->
    value="{{ mood_input or '' }}"  <!-- re-fills the input after a POST -->
  />
  <button type="submit">Match mood</button>
</form>
Jinja2 syntaxWhat it does
{{ variable }}Outputs a Python value into the HTML
{% if condition %} ... {% endif %}Conditionally renders a block of HTML
{% for key, data in movies.items() %}Loops over the dictionary, giving access to each key and value
{{ result.title }}Accesses the title field inside the result dictionary
{{ mood_input or '' }}Uses Python's or to show an empty string if mood_input is None
In index.html, what does {% if result and result.mood == key %} do?
Correct. It applies the hit class only to the row whose key matches the AI's result — turning that row blue so students can see exactly which key was looked up.
Look again at where this tag appears — it's inside the {% for %} loop, on the class attribute of each row. It adds the hit class to highlight the matched row.

Running the project
Setup commands from scratch

Run these commands once, in order, from inside the movie-mood-matcher/ folder.

Terminal — Mac / Linux 
# 1. Create a virtual environment
python3 -m venv venv

# 2. Activate it — you'll see (venv) in your prompt
source venv/bin/activate

# 3. Install packages
pip install -r requirements.txt

# 4. Create .env and add your key
cp .env.example .env
# open .env and set: ANTHROPIC_API_KEY=sk-ant-xxxxx

# 5. Start Flask
python app.py
Terminal — Windows 
# 1. Create a virtual environment
python -m venv venv

# 2. Activate it
venv\Scripts\activate

# 3. Install packages
pip install -r requirements.txt

# 4. Create .env and add your key
copy .env.example .env
# open .env and set: ANTHROPIC_API_KEY=sk-ant-xxxxx

# 5. Start Flask
python app.py

Then open http://127.0.0.1:5000 in your browser. You should see the full UI.

✅
Next time you work on it — you only need steps 2 and 5. The venv and packages are already installed. Just activate and run.
⚠️
Common errors
ModuleNotFoundError — you're not inside the venv. Run the activate command first.
AuthenticationError — check that .env exists in the project root and the key is correct with no spaces.
No such file or directory: requirements.txt — you're not inside the movie-mood-matcher/ folder. Run cd movie-mood-matcher first.
