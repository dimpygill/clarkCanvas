Introduction to Agents: Rule-Based vs LLM-Powered

Python Tutorial · Student Support Example

How this tutorial is organized: Part A explains the concepts. Part B builds a rule-based agent. Part C adds Claude to the same agent. Part D compares both versions. In each part, the general structure comes first, followed by the Student Support example.

Part A — Concepts

1. What is an agent?

An agent is a system that receives information about its environment, makes a decision, and takes an action toward a goal. A simple teaching model is Observe → Decide → Act. Some agents use fixed rules; others use AI models. Not every program that contains an if-statement is meaningfully autonomous.

2. Two types of agents

Rule-based agent

A rule-based agent uses rules written in advance by a programmer, in the form if CONDITION, then ACTION; otherwise, OTHER ACTION. It does not learn from data or invent its own criteria.

LLM-powered agent

An LLM-powered agent uses a large language model (such as Claude) to interpret information, generate responses, and sometimes select tools or actions. Rules can still make the core decisions while the LLM handles language tasks; that is an LLM-assisted workflow. To make it more agentic, the system could choose among approved tools, check results, and take authorized follow-up actions.

3. The example used throughout: Student Support Agent

We have an Excel file named student_progress.xlsx with these columns: Student ID, Student Name, Attendance (%), Assignment Score (%).

The rule: if attendance is below 70% OR assignment score is below 60%, mark the student as Needs Help; otherwise, Doing Well. We use OR, so meeting either low-performance condition triggers support.

Part B — Rule-Based Version

4. General structure of a rule-based agent program

  1. Observe: Read the input data (here, an Excel file).
  2. Loop: Process one record at a time.
  3. Decide: Apply the fixed if/else rule to that record.
  4. Act: Record the decision and recommended action.
  5. Save: Write all results to an output file.

5. Example: complete beginner Python program

No lambda, no apply(), and no machine learning.

import pandas as pd

students = pd.read_excel("student_progress.xlsx")
statuses = []
actions = []

for index, student in students.iterrows():
    name = student["Student Name"]
    attendance = student["Attendance (%)"]
    score = student["Assignment Score (%)"]

    if attendance < 70 or score < 60:
        status = "Needs Help"
        action = "Offer a support meeting"
    else:
        status = "Doing Well"
        action = "Send an encouragement message"

    statuses.append(status)
    actions.append(action)
    print(name, "-", status, "-", action)

students["Status"] = statuses
students["Recommended Action"] = actions
students.to_excel("student_support_results.xlsx", index=False)
print("Results saved to student_support_results.xlsx")

6. Understand the code step by step

  1. import pandas as pd: Load the pandas library so Python can read and write Excel data.
  2. read_excel: Read the input workbook into a table called students. (Observe)
  3. statuses and actions: Create empty lists to collect results for each student.
  4. for ... iterrows(): Process students one at a time, like a foreach loop in C#. (Loop)
  5. name, attendance, score: Read the current student's values.
  6. if attendance < 70 or score < 60: Apply the fixed rule. Otherwise use else. (Decide)
  7. append: Add each decision and recommended action to the corresponding list. (Act)
  8. print: Show the current student's result in the terminal.
  9. students["Status"] = statuses: Add a result column to the table; do the same for recommended actions.
  10. to_excel: Save all student records and results in student_support_results.xlsx. (Save)

7. Run the project

  1. Put student_agent_simple.py and student_progress.xlsx in the same folder.
  2. Open a terminal in that folder and run python -m pip install pandas openpyxl.
  3. Run python student_agent_simple.py.
  4. Open student_support_results.xlsx to review decisions.

8. Why is this rule-based, and is it really an AI agent?

The thresholds (70 and 60), labels, and recommended actions are all predefined. Changing the rules requires changing the code. The program does not use an AI model or independently interpret the students' circumstances. Here, “Act” means recording a recommendation; it does not actually send messages or book meetings.

It is traditional, deterministic programming. In an introductory AI course, it can illustrate a simple rule-based agent architecture because it reads observations, chooses actions using a policy, and produces action recommendations. It is not an LLM-powered agent, and calling every if/else program an autonomous agent would be misleading.

Part C — Same Problem with Claude

9. General structure of the Claude version

The Excel input and rule-based decisions remain unchanged. Claude is added to generate personalized draft messages. This is LLM-assisted automation, not yet a fully autonomous agent.

Observe → Decide → Generate → Save

  1. Observe: pandas reads each student’s name, attendance, and assignment score from Excel.
  2. Decide: Python uses the same rule: attendance below 70% OR assignment score below 60% means Needs Help; otherwise Doing Well.
  3. Generate: Python sends a prompt to Claude containing the fictional student data and the status. Claude drafts a short, supportive message.
  4. Save: The program records the status, suggested action, and Claude message in a new Excel workbook. No emails are sent.

10. Standard Claude API request structure

Before using Claude in any Python application, understand the reusable request pattern below. The student-support example is only one possible application.

response = client.messages.create(
    model="MODEL_ID",
    max_tokens=150,
    system="Optional instructions about Claude's behavior",
    messages=[
        {"role": "user", "content": "Your request goes here"}
    ]
)
PartPurpose
client.messages.create(...)Calls Claude's Messages API and returns a response object.
modelChooses an available Claude model by its model ID.
max_tokensSets the maximum number of tokens Claude may generate; it does not specify the input length.
systemOptional high-level behavior instructions, such as being a supportive teacher. It is a separate parameter, not a message role.
messagesA list of conversation messages, in order.
roleIdentifies the speaker: user (the application/person requesting something) or assistant (Claude's previous message in conversation history).
contentHolds the actual text or other supported content of that message.

The system line is optional and may be omitted. For a new independent request, one user message is enough. For follow-up conversations, include prior user and assistant messages in order.

11. Standard Claude API response structure

The API does not return only a plain sentence. It returns a structured Message object. This is a simplified illustrative shape of a successful text response, not a literal JSON response copied from the service:

{
  "id": "msg_example",
  "type": "message",
  "role": "assistant",
  "model": "MODEL_ID",
  "content": [
    {"type": "text", "text": "Generated response goes here."}
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 45,
    "output_tokens": 12
  }
}
Response fieldWhat it tells you
idUnique identifier assigned to the response.
typeObject type; normally message.
roleassistant, because Claude is replying.
modelModel used for the reply.
contentList of content blocks. Text replies commonly include a block with type: text and a text value. Other applications may receive tool-use or other block types.
stop_reasonWhy generation stopped. end_turn means Claude finished; max_tokens means it reached the output limit. Other reasons are possible.
stop_sequenceA matching custom stop sequence, if one was used; otherwise typically null.
usageToken-usage information, including input and output token counts. Actual usage objects can contain additional fields.

12. Reading the response in Python

# The SDK returns a Message object, not a Python dictionary.
print(response.role)          # assistant
print(response.stop_reason)   # e.g. end_turn
print(response.usage.output_tokens)

# For a response whose first content block is text:
message = response.content[0].text
print(message)

Why response.content[0].text? response is the full reply object; content is its list of blocks; [0] selects the first block; and .text reads its generated text. This shortcut works for the simple text-only Student Support Agent, but other applications should inspect each block's type before assuming it contains text.

Reusable idea: A future application can change the prompt, system instructions, model, and processing logic while using the same general request/response structure.
