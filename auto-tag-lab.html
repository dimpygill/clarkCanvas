Auto-Tag: build an AI-powered list, end to end.

You'll build a small web app where a browser page talks to a Python backend, the backend asks an AI model to categorize whatever you typed, and the result gets stored in a real cloud database. 01 What you're building

The whole round trip, in four boxes

Nothing here is magic — it's four ordinary programs talking over HTTP. Every "Add" click follows this exact path.

BrowserHTML + JS
→
Flask backendapp.py
→
Groq APIcategorize
→
Airtablecloud storage
The browser sends your typed text to Flask. Flask asks Groq's model to guess a category. Flask writes the item and its category to Airtable as one row, then sends the result back so the page can re-render. Notice what the browser never does: it never talks to Groq or Airtable directly. Flask is the only thing holding your API keys — that's the whole reason the backend exists.

Project structure

Your folder should end up looking exactly like this.

Auto-Tag/ ├── .venv/ (created in Part 05) ├── .env (created in Part 05 — your real secrets) ├── .env.example ├── app.py ├── requirements.txt └── templates/ └── index.html
index.html must live inside a folder named exactly templates. That's a Flask convention, not a setting you can change — render_template() only looks there. If it sits next to app.py instead, the page will crash with TemplateNotFound.

app.py
"""
Simple List — Flask backend that stores items in Airtable, now with
AI auto-categorization.

THE FLOW, step by step:
  1. Browser loads this page                          -> GET  /
  2. User types text, clicks "Add"                     -> POST /api/items
  3. Flask receives the POST                           -> calls an LLM to
     guess a category for the item ("Grocery", "Task", ...)
  4. Flask sends the item's name + category to Airtable -> stored as a row
  5. Flask returns the updated list to the browser      -> the page re-renders it

This is the same pattern used everywhere AI gets bolted onto an app:
your backend calls an LLM with a prompt, gets text back, validates it,
and treats it like any other piece of data. This app uses Groq's free
tier (no credit card required) — swap in any other provider and this
same pattern still holds, only the client setup changes.

Run with:  python app.py
Then open: http://127.0.0.1:5000
"""

import os
import requests
from flask import Flask, render_template, request, jsonify
from dotenv import load_dotenv
from groq import Groq

load_dotenv()  # reads AIRTABLE_* and GROQ_API_KEY from a local .env file

AIRTABLE_TOKEN = os.environ["AIRTABLE_TOKEN"]
BASE_ID = os.environ["AIRTABLE_BASE_ID"]
TABLE_NAME = os.environ["AIRTABLE_TABLE_NAME"]

AIRTABLE_URL = f"https://api.airtable.com/v0/{BASE_ID}/{TABLE_NAME}"
HEADERS = {
    "Authorization": f"Bearer {AIRTABLE_TOKEN}",
    "Content-Type": "application/json",
}

# The Groq client reads GROQ_API_KEY from the environment automatically.
groq_client = Groq()

CATEGORIES = ["Grocery", "Task", "Work", "Personal", "Other"]

app = Flask(__name__)


def categorize_item(name: str) -> str:
    """
    Ask an LLM to sort one list item into a fixed set of categories.

    This is the smallest possible example of the "LLM as a function" pattern:
    text goes in, one constrained piece of text comes out, and the rest of
    the program treats it like any other value.
    """
    prompt = (
        "Classify the following to-do/list item into exactly one of these "
        f"categories: {', '.join(CATEGORIES)}.\n"
        f"Item: {name}\n"
        "Respond with only the category word and nothing else."
    )
    try:
        response = groq_client.chat.completions.create(
            model="llama-3.1-8b-instant",
            max_tokens=10,
            temperature=0,
            messages=[{"role": "user", "content": prompt}],
        )
        guess = response.choices[0].message.content.strip()
        # Validate: only trust the model's answer if it's actually one of
        # our categories. Never let raw model output flow into the database
        # unchecked.
        return guess if guess in CATEGORIES else "Other"
    except Exception as e:
        print("categorize_item failed:", e)
        # If the AI call fails for any reason, the app should still work —
        # it just falls back to an uncategorized item instead of crashing.
        return "Other"


@app.route("/")
def index():
    """Serve the single HTML page."""
    return render_template("index.html")


@app.route("/api/items", methods=["GET"])
def get_items():
    """Ask Airtable for every record currently in the table."""
    response = requests.get(AIRTABLE_URL, headers=HEADERS)
    response.raise_for_status()
    records = response.json()["records"]
    items = [
        {
            "id": record["id"],
            "name": record["fields"].get("Name", ""),
            "category": record["fields"].get("Category", ""),
        }
        for record in records
    ]
    return jsonify(items)


@app.route("/api/items", methods=["POST"])
def add_item():
    """Take text from the browser, categorize it with Claude, and store both
    the text and the category as a new record in Airtable."""
    data = request.get_json(silent=True) or {}
    name = (data.get("name") or "").strip()
    if not name:
        return jsonify({"error": "name is required"}), 400

    category = categorize_item(name)

    payload = {"fields": {"Name": name, "Category": category}}
    response = requests.post(AIRTABLE_URL, headers=HEADERS, json=payload)
    response.raise_for_status()
    record = response.json()
    return jsonify({
        "id": record["id"],
        "name": record["fields"]["Name"],
        "category": record["fields"].get("Category", ""),
    }), 201


@app.route("/api/items/<record_id>", methods=["DELETE"])
def delete_item(record_id):
    """Delete one record from Airtable by its record id."""
    response = requests.delete(f"{AIRTABLE_URL}/{record_id}", headers=HEADERS)
    response.raise_for_status()
    return jsonify({"deleted": record_id})


if __name__ == "__main__":
    app.run(debug=True, port=5000)

async function loadItems(){

  const res = await fetch('/api/items');

  renderList(items);
  statusEl.textContent = `${items.length} item${items.length===1?'':'s'} in Airtable`;

function renderList(items){
  listEl.innerHTML = '';
  if(items.length === 0){
    listEl.innerHTML = '<li class="empty">no items yet</li>';
    return;
  }
  items.forEach(item => {
    const li = document.createElement('li');

    const left = document.createElement('div');
    left.className = 'item-left';

    const span = document.createElement('span');
    span.className = 'name';
    span.textContent = item.name;
    left.appendChild(span);

      const badge = document.createElement('span');
      badge.className = 'badge ' + item.category;
      badge.textContent = item.category;
      left.appendChild(badge);

    const del = document.createElement('button');
    del.textContent = 'remove';
    del.addEventListener('click', () => deleteItem(item.id));

    li.appendChild(left);
    li.appendChild(del);
    listEl.appendChild(li);
  });
}

async function deleteItem(id){

Read categorize_item() carefully — it's the smallest complete example of the pattern behind almost every AI feature: build a prompt, call the model, check the answer against a fixed list of allowed values, and only then let it near your database. The try/except around it matters too: if the AI call fails, the app still saves the item instead of crashing.

09 Troubleshooting

Errors you're most likely to hit

Every one of these has been hit by someone building this exact app. Find your error message below.

'pip' is not recognized as the name of a cmdlet...
Your virtual environment isn't active. In PowerShell, run .venv\Scripts\Activate.ps1 — note the .ps1, not .bat. A .bat file runs in a throwaway subprocess in PowerShell, so its changes vanish immediately. Confirm you see (.venv) in your prompt before continuing.
jinja2.exceptions.TemplateNotFound: index.html
Flask can't find your template. index.html must be inside a folder named exactly templates, next to app.py — not beside it. Create the folder, move the file in, and refresh.
Every item is tagged "Other"
The AI call is failing and hitting the fallback. Look in your terminal for a categorize_item failed: line — it names the real cause, usually an invalid or missing GROQ_API_KEY, or a key that's still the placeholder from .env.example. Fix .env, then restart the server.
KeyError: 'AIRTABLE_TOKEN'
Python can't find that variable. Either your .env file doesn't exist yet, it's named something else (like .env.txt), or it isn't in the same folder as app.py. Check the exact filename in VS Code's Explorer.
401 / 403 from Airtable, or NOT_FOUND
Three things to check: your AIRTABLE_BASE_ID is the app... ID and not the base's display name; your token has both read and write scopes; and the token was explicitly granted access to this base when you created it.
422 from Airtable when adding an item
Your field names don't match. The table needs fields named exactly Name and Category, with matching capitalization. Airtable is strict about this.
Nothing at all appears in the terminal when you click Add
The browser isn't reaching the server you're watching — usually a stale Flask process from an earlier run is still holding port 5000. Stop the server with Ctrl+C, end any leftover python.exe processes in Task Manager, start it again, and open a fresh browser tab.
Blank rows in the list
Not a bug in your code — those are empty records sitting in Airtable itself, usually left over from testing. Delete them from the Airtable grid view or click "remove" in the app.
Code changes seem to have no effect
Save the file (Ctrl+S), then restart the server: Ctrl+C, then python app.py. Also confirm you're editing the file in the folder you're actually running from.
10 Stretch goals

Prompt engineering

Change the categories

Edit CATEGORIES to fit your own life, then observe how the model's answers shift with no other code change.

Error handling

Structured output

Multi-item entry

Let a user type "milk, eggs, call mom" and have the model return a JSON list, creating three separate rows.

New route

Add a summarize button

Build a GET /api/summary route that sends the whole list to the model and returns one sentence about it.

Frontend

Filter by category

Add buttons that show only Grocery, only Task, and so on — all in the browser, with no new backend code.

Embeddings

Detect near-duplicates

Warn when a new item is semantically close to an existing one ("buy milk" vs "get milk") using embeddings and cosine similarity.

Worth noticing: this project originally called a different AI provider's API and was switched to Groq by changing three lines — the import, the client, and the field the response is read from. The prompt, the validation, and the fallback never changed. The "LLM as a function" pattern is provider-agnostic; only the plumbing differs.
